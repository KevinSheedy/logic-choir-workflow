<Steps>
1. **New empty project**, saved into `01_logic/`. In *File → Project Settings → Audio*, set the **sample rate to match the recording** (check the WAV's info, usually 48 kHz). Set *Project Settings → Assets* to **copy audio files into project**.
2. **Import** the stereo WAV by dragging it onto a new stereo audio track. If the recorder made two mono files (L and R), import both, pan them hard left and right, or merge them into a stereo file.
3. **Set one gain for the whole concert, by hand.** A 32-bit float file may peak above 0 dBFS or sit very low. Find the loudest **sung** passage and set **non-destructive region gain** (Region inspector → *Gain*) so it peaks around **−6 dBFS**. That leaves headroom for processing. Using one gain for every song keeps the songs' natural levels relative to each other, and the shared processing behaves the same on each. Applause may then go above 0 dBFS, which is harmless here. It gets turned down per song in [Applause and gaps](/logic-choir-workflow/editing/applause-and-gaps/).
4. **Mark the songs.** Play through (or skim the waveform) and add a **marker** at the start of each song you might use (`Option`‑`'` adds a marker at the playhead). Rename the markers with song titles.
5. **Save as a template.** Once the channel strip (EQ, reverb send etc.) settles down, use *File → Save as Template…* so the next concert starts from it.
</Steps>

<Aside type="caution" title="Don't use Normalize Region Gain on the concert">
*Normalize* sets the gain from the loudest **peak** in the region. Our applause is louder than the singing, so a clap sets the gain and every song ends up too quiet. Don't normalise each song separately either: that pushes a quiet ballad up to the same peak as the loudest song.
</Aside>

<Aside type="tip">
Logic processes audio internally in floating point, so a channel showing red above 0 dB isn't harmful *inside* the mix. It only clips when it reaches the output or a bounce. Keeping peaks around −6 dBFS is still a good habit, because plugins behave more predictably there.
</Aside>

## Project per concert, or one per song?
Use **one project per concert**, with songs as sections of the timeline (or separate projects bounced from it). One project means one set of processing to tweak and consistent sound across songs. Revisit this choice after the first two concerts.
